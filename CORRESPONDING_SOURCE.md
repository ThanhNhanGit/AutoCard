# Corresponding source and binary provenance

This document records the provenance of executable files distributed in AutoCard. It is intended to
make license review and reproducible replacement practical. SHA-256 values refer to the files stored
through Git LFS on the `master` branch at AutoCard commit
`657f96e0838e5167257f5c0dff4f8f8a51d1bfb9`.

The complete checksum inventory for every Git LFS object is in
[`BINARY_MANIFEST.sha256`](BINARY_MANIFEST.sha256).

## Maintaining this record

When replacing a binary:

1. record the exact version and upstream release or commit;
2. record its complete build configuration where licensing can change by build flags;
3. calculate SHA-256 after extraction;
4. include every required license and notice;
5. preserve equivalent, durable access to complete corresponding source;
6. never distribute a build reporting `--enable-nonfree`.

For GPL-covered binaries, a generic link to an upstream homepage is not enough if it cannot identify
the exact source used. Keep immutable commit links and, for future releases, attach a source archive
generated by the build system alongside each binary release.

## Source request

If an immutable upstream archive becomes unavailable, open a
[Source Request issue](https://github.com/ThanhNhanGit/AutoCard/issues/new) identifying the AutoCard
commit, file name, and SHA-256. The maintainer will provide or restore network access to the
corresponding source at no charge while that binary remains distributed.
